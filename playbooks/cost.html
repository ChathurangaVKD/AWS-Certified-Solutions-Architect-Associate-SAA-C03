    Lesson 3 · 12 min

    Storage: put each byte in the cheapest tier that still meets access needs

    S3 classes

    recap
    • Unknown or changing access → Intelligent-Tiering (no retrieval fees)
    • Known pattern → lifecycle rules: Standard → Standard-IA (30 d) → Glacier tiers
    • Reproducible data, one AZ is fine → One Zone-IA
    • Archive, hours to restore OK → Glacier Deep Archive (cheapest)

    S3 hygiene

    hidden cost
    • Expire old noncurrent versions
    • Abort incomplete multipart uploads after N days
    • S3 Storage Lens: org-wide usage and savings insights
    • Requester Pays: downloader pays transfer + requests

    EBS

    quick wins
    • gp2 → gp3: ~20% cheaper per GB, 3,000 IOPS baseline at any size; change online
    • Delete unattached volumes
    • Old snapshots → Snapshot Archive (~75% cheaper, 24–72 h restore)
    • Data Lifecycle Manager automates snapshot retention
    • st1/sc1 HDD for big sequential data

    EFS and FSx

    file
    • EFS lifecycle to Infrequent Access and Archive
    • One Zone storage class when multi-AZ is not needed
    • FSx: HDD storage and data deduplication (Windows)
    NeedCheapest that works
    Shared files for many Linux instancesEFS (+ IA lifecycle), not EBS copies
    Static website assetsS3 + CloudFront, not EC2 disks
    Logs kept 7 years, rarely readS3 lifecycle → Glacier Deep Archive
    Database backups for complianceSnapshots/AWS Backup with cold-storage tier

    NAT gateway vs gateway endpoint

    Through NAT gateway / month
    Through gateway endpoint
    Saved per year

    NAT data processing ≈ $0.045/GB (us-east-1), plus the hourly NAT charge. Gateway endpoints for S3 and DynamoDB have no charge.

    Rules: traffic into AWS is free. Out to the internet costs most. Cross-Region costs. Cross-AZ costs a little each way. Same AZ over private IPs is free. Put CloudFront in front of heavy egress, use gateway endpoints for S3/DynamoDB, keep chatty services in one AZ when HA allows.
    Lesson 5 · 12 min

    Design patterns that cut the bill

    Match capacity to demand

    elastic
    • Auto Scaling with target tracking
    • Stop dev/test at night (Instance Scheduler, EventBridge + Lambda)
    • RDS can be stopped up to 7 days, then restarts
    • Aurora Serverless v2, DynamoDB on-demand for spiky or unknown load

    Serverless for idle time

    pay per use

    Lambda, API Gateway, Fargate, DynamoDB, S3: nothing to pay while idle. Great for intermittent, event-driven workloads. Steady high traffic can be cheaper on EC2 with Savings Plans.

    Cache instead of scale

    read-heavy

    CloudFront, ElastiCache or DAX absorb reads so the database can stay smaller. Read replicas for reporting instead of a bigger primary.

    Cheaper silicon

    Graviton

    Arm-based Graviton instances: better price-performance for most Linux workloads (up to ~40% vs comparable x86).

    Decouple with queues

    smooth peaks

    SQS lets workers scale on queue depth and run on Spot instead of provisioning for the peak.

    Managed beats self-managed

    ops cost

    "Least operational overhead" usually also wins on total cost: RDS over databases on EC2, Fargate over self-managed clusters.
