    An instance type is a recipe of CPU, memory, disk and network

      T: burstable

      credits

      Cheap baseline CPU, earns credits while idle and spends them to burst. In unlimited mode it can keep bursting for an extra charge.

      "spiky, mostly idle" → T. "Constant high CPU" → not T.

      Graviton

      g suffix

      AWS Arm processors. Best price-performance for most Linux workloads. Software must support Arm.

      Nitro System

      platform

      AWS's modern hypervisor and hardware. Faster networking and EBS, better security, needed for many features (io2 Block Express, Multi-Attach).

      Lesson 2 · 12 min

      Launching an instance, and what happens when you stop it

      AMI

      template

      The image an instance boots from: OS, software, settings, EBS snapshot mappings.

      • Regional. Copy an AMI to use it in another Region
      • Share with other accounts or publish to Marketplace
      • Golden AMI = pre-baked software for fast boot
      • EC2 Image Builder automates building and testing AMIs

      User data

      boot script

      A script that runs as root on first boot only (by default). Installs packages, pulls config.

      Slow boot from user data? Bake it into an AMI.

      Instance metadata (IMDS)

      169.254.169.254

      The instance asks about itself: ID, AZ, IPs, role credentials, user data.

      IMDSv2 requires a session token (PUT first). Enforce it to block SSRF credential theft.

      Launch template

      use this

      Saved launch settings: AMI, type, key, security groups, user data, role. Versioned. Used by Auto Scaling, EC2 Fleet, Spot Fleet. Launch configurations are the old, deprecated version.

      Stop, hibernate, terminate: what survives?

      Action
      ItemAfter the action

      Hibernate rules

      • RAM is written to the encrypted EBS root volume
      • RAM must fit in the root volume (max 150 GB RAM)
      • Up to 60 days hibernated
      • Use for slow-starting apps that need warm memory

      Termination protection

      Blocks accidental terminate from the console or API. Doesn't stop Auto Scaling from terminating, or a shutdown from inside the OS if behavior is "terminate".

      Access

      Key pair for SSH, EC2 Instance Connect (temporary key pushed by IAM), or Session Manager (no port 22, no keys).

      When does a commitment pay off?

      runs 24 h / day

      Example instance at $0.10/hour On-Demand, 730 hours per month, using each option's maximum discount. A commitment is billed every hour whether the instance runs or not. Spot can be interrupted.

      RI details

      • Standard: biggest discount, can change AZ and size within the family; sell on the RI Marketplace
      • Convertible: up to 66%, exchange for another family, OS or tenancy
      • Pay all, partial or no upfront (more upfront = more discount)
      • Zonal RI also reserves capacity in that AZ; regional RI does not

      Spot details

      • 2-minute interruption notice (metadata + EventBridge)
      • On interruption: terminate, stop or hibernate
      • Spot Fleet / EC2 Fleet: mix types and AZs; use price-capacity-optimized allocation
      • Cancelling a Spot request doesn't terminate running instances
      • Never for databases or anything stateful you can't lose

      Capacity extras

      • Capacity Reservation + regional RI or Savings Plan = capacity and discount
      • Capacity Blocks for ML: reserve GPU instances for a future date range

      Close together = fast network, shared risk. Far apart = isolated failures.

      Instance networking

      ENI

      Virtual network card: private IPs, MAC, security groups. Move a secondary ENI to a standby instance in the same AZ for quick failover.

      Public IP vs Elastic IP

      Auto-assigned public IPv4 changes on stop/start. An Elastic IP is static until you release it. All public IPv4 is billed hourly.

      ENA (enhanced networking)

      SR-IOV networking, higher bandwidth (100 Gbps and more), lower latency, more packets per second. On by default on current instances.

      EFA

      Elastic Fabric Adapter: ENA plus OS-bypass for HPC and ML using MPI or NCCL. Pair with a cluster placement group.

      "HPC, tightly coupled, MPI" → EFA

      Lesson 5 · 15 min

      Auto Scaling groups add and remove instances for you

      You set min, max and a policy. The group keeps the desired count healthy, spread across AZs.

      Target tracking simulator

      Desired instances
      Average CPU per instance

      Traffic 230 = the work of 2.3 instances running at 100% CPU. Desired = traffic ÷ target, rounded up, kept between min and max.

      Scaling policies

      PolicyHow it worksExam keyword
      Target trackingKeep a metric at a value, like a thermostat. AWS creates the alarms"keep average CPU at 50%"
      Step scalingCloudWatch alarm thresholds add or remove different amounts"add 2 at 70%, add 4 at 90%"
      Simple scalingOne adjustment per alarm, then waits for the cooldownOlder, rarely the best answer
      ScheduledChange min/max/desired at set times"every Monday at 9:00"
      PredictiveML forecast from history, scales ahead of daily/weekly patterns"recurring pattern, scale before load arrives"

      Good metrics: CPUUtilization, ALB RequestCountPerTarget, network in/out, or a custom metric like SQS backlog per instance.

      Health checks

      Default: EC2 status checks only. Turn on ELB health checks so the ASG replaces instances whose app fails behind the load balancer. Grace period lets new instances boot first.

      Cooldown and warm-up

      Default cooldown 300 s stops extra scaling while new instances start. Instance warm-up excludes new instances from metrics until ready.

      Lifecycle hooks

      Pause an instance in Pending:Wait or Terminating:Wait to run scripts: install software, or copy logs before termination.

      Termination order

      Default: first balance AZs (remove from the AZ with most instances), then the oldest launch template or configuration.

      Mixed instances policy

      One ASG with several instance types and a mix of On-Demand and Spot (e.g. base 2 On-Demand, the rest 70% Spot).

      Warm pools and instance refresh

      Warm pool: pre-initialised stopped instances for fast scale-out. Instance refresh: roll out a new AMI or launch template gradually.

      ASGs are regional, not global. They span AZs in one Region. For multi-Region, run an ASG in each Region and route with Route 53 or Global Accelerator.

      Classic Load Balancer (CLB) is legacy. On the exam it's almost never the right answer.

      ALB listener rules

      Incoming request

      Rules are checked in priority order. The first match wins; nothing matches → default action.

      Cross-zone load balancing

      Cross-zone load balancing

      Health checks

      LB sends requests to a path (e.g. /health). Unhealthy targets get no traffic until they pass again.

      Deregistration delay

      (Connection draining.) A target being removed finishes in-flight requests first. Default 300 s, range 0–3600.

      Sticky sessions

      Same user → same target. ALB uses cookies (duration-based or app cookie). Can cause uneven load. Better: store sessions in ElastiCache or DynamoDB.

      SSL/TLS and SNI

      Terminate HTTPS on the LB with an ACM certificate. SNI lets ALB and NLB serve many domains with many certificates on one listener.

      Security groups

      Allow 80/443 from the internet to the ALB. Instances allow traffic only from the ALB's security group.

      Need static IPs for an ALB?

      Put Global Accelerator (or an NLB) in front of it.
