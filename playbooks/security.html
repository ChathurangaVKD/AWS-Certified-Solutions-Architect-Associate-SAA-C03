    Lesson 1 · 5 min

    AWS secures the cloud. You secure what you put in it.

    The shared responsibility model. The exam tests it with "who is responsible for…" questions.

    AWS: security of the cloud

    Data centers, hardware, disk destruction, the global network, the hypervisor, and the software of managed services (RDS engine patches, Lambda runtime OS).

    You: security in the cloud

    Your data, IAM, encryption choices, security groups and NACLs, the EC2 guest OS and its patches, your application code.

    The more managed the service, the less you do. EC2: you patch the OS. RDS: AWS patches the engine, you choose settings and access. Lambda / S3 / DynamoDB: you handle data, permissions and code only.

    Sort it: AWS or You?

    Lesson 2 · 12 min

    KMS: AWS's key safe

    KMS (Key Management Service) creates and guards encryption keys. The key never leaves KMS. You send data or small keys in, encrypted data comes out.

    Three kinds of KMS keys

    AWS owned

    invisible

    Used inside AWS services for you. You can't see, manage or audit them. Free.

    e.g. DynamoDB default encryption, SSE-S3

    AWS managed

    aws/service

    In your account, named aws/s3, aws/ebs, aws/rds. You can see and audit use. You can't edit the key policy.

    • Rotated automatically every year
    • Can't be shared with other accounts

    Customer managed

    full control

    You create it, you write the key policy.

    • Optional automatic rotation (yearly default)
    • Can share cross-account
    • Can disable, or delete after a 7–30 day wait

    Exam: "control over key", "cross-account", "audit"

    Envelope encryption, step by step

    KMS can encrypt only 4 KB directly. For bigger data, KMS gives you a data key, and you encrypt locally.

    1. Ask KMS for a data key. GenerateDataKey returns two copies: a plaintext data key and the same key encrypted by your KMS key.
    2. Encrypt your data on your side with the plaintext data key (fast, any size).
    3. Throw away the plaintext key. Store the encrypted data key next to the encrypted data.
    4. To read it back, send the encrypted data key to KMS Decrypt. You get the plaintext key, then decrypt the data locally.

    S3, EBS and RDS do this for you behind the scenes. You only choose the KMS key.

    KMS facts the exam loves

    Key policy

    Every KMS key has one, and it's the main gate. IAM policies work for a key only if its key policy allows the account.

    Regional

    Keys live in one Region. Copying an encrypted snapshot to another Region means re-encrypting with a key there.

    Multi-Region keys

    Same key material and ID in several Regions. Encrypt in one, decrypt in another. For global apps and client-side encryption.

    Audited

    Every use of a KMS key is logged in CloudTrail. That's why "audit who used the key" points to SSE-KMS.

    Throttling

    KMS has request quotas. Heavy S3 traffic with SSE-KMS can be throttled. Fix: S3 Bucket Keys (up to 99% fewer KMS calls).

    Imported key material

    Bring your own key. No automatic rotation; you rotate manually. You can delete the material immediately.

    KMS vs CloudHSM

    KMSCloudHSM
    TenancyMulti-tenant, fully managedSingle-tenant HSM in your VPC
    Who controls keysAWS manages the hardware, you manage keys via APIOnly you. AWS cannot recover your keys
    IntegrationNative with most AWS servicesVia KMS custom key store, or apps (PKCS#11, JCE)
    Exam keywords"managed", "integrated", "audit""dedicated / single-tenant HSM", "full control", "SSL offload", "Oracle TDE"

    Older questions say "FIPS 140-2 Level 3 → CloudHSM". KMS is now also validated at Level 3, so look for "single-tenant" or "you alone control the hardware".

    Lesson 3 · 12 min

    Encrypting S3, EBS, RDS and friends

    At rest = stored on disk. In transit = moving over the network (TLS/HTTPS).

    S3 encryption options

    Pick a requirement. The right option lights up.

    OptionWho holds the keyKey-use auditRemember
    SSE-S3S3 (AWS owned)NoDefault for all new objects since 2023. AES-256. Free.
    SSE-KMSKMS key (AWS managed or yours)Yes, CloudTrailSeparate permission on the key. Watch KMS quotas → Bucket Keys.
    DSSE-KMSKMS keyYesTwo layers of encryption, for strict compliance rules.
    SSE-CYou, sent in every requestNoAWS never stores your key. HTTPS required.
    Client-sideYou, before uploadYour choiceData is already encrypted when it reaches AWS.

    Encrypting something that already exists

    EBS volume

    1. Snapshot the unencrypted volume
    2. Copy the snapshot with encryption turned on
    3. Create a new volume from the copy and swap it in

    Turn on "EBS encryption by default" per Region to avoid this. Snapshots of encrypted volumes are encrypted.

    RDS / Aurora database

    1. Take a snapshot of the unencrypted DB
    2. Copy the snapshot with encryption on
    3. Restore a new DB from it, then switch the app

    You can't turn encryption on for a running DB. Read replicas have the same encryption as the primary.

    Sharing an encrypted snapshot with another account? It must use a customer managed key, and you must share that key too. Snapshots encrypted with an AWS managed key can't be shared.

    Other services, in one line each

    ServiceAt restIn transit
    DynamoDBAlways encrypted (choose AWS owned, AWS managed or your key)HTTPS
    EFSChoose at creationTLS via the EFS mount helper
    RDSKMS, set at creationSSL/TLS; can force it with a parameter group setting
    RDS loginIAM database authentication (MySQL, MariaDB, PostgreSQL): a token instead of a password
    Redshift / ElastiCacheKMSTLS. ElastiCache Redis/Valkey: AUTH token for access
    Site-to-Site VPN—IPsec encrypted
    Direct Connect—Not encrypted by default. Use a VPN over DX, or MACsec

    AWS Certificate Manager (ACM)

    What it does

    Free public TLS certificates that renew automatically. Imported certificates don't auto-renew.

    Where they go

    ALB, NLB, CloudFront, API Gateway. On the exam, not installed directly on EC2.

    The Region trap

    CloudFront needs the certificate in us-east-1. An ALB needs it in the ALB's own Region.

    Private CA

    AWS Private CA issues internal certificates for private apps and mTLS.

    Who signs in: directories and users

    AWS Managed Microsoft AD

    Real AD run by AWS. Can trust your on-prem AD. Use when apps need AD features in AWS.

    AD Connector

    A proxy to your on-prem AD. Stores nothing in AWS. Needs VPN/DX.

    Simple AD

    Small, cheap, standalone AD-compatible directory. Can't trust on-prem AD.

    Cognito

    Your app's users. User pool = sign-up/sign-in. Identity pool = temporary AWS credentials.

    IAM Identity Center

    Your employees, single sign-on to many AWS accounts.

    Lesson 5 · 12 min

    Security groups and NACLs

    Two firewalls in every VPC. The difference is a guaranteed exam question.

    Security groupNetwork ACL
    ProtectsAn instance (its network interface)A whole subnet
    StateStateful: replies are allowed automaticallyStateless: replies need their own rule
    RulesAllow onlyAllow and Deny
    OrderAll rules checked togetherLowest rule number first, first match wins
    DefaultDeny all in, allow all outDefault NACL allows all. A new custom NACL denies all
    SpecialCan reference another security groupNeeds ephemeral ports 1024–65535 for replies
    "Block one bad IP address" → NACL deny rule. Security groups can't deny.

    Packet simulator

    A visitor opens your website on HTTPS (port 443) on an EC2 instance in a public subnet. Change the rules and follow the packet.

    Other network tools

    VPC endpoints

    Gateway: S3 and DynamoDB only, free, added to route tables. Interface (PrivateLink): most services, an ENI with a private IP, costs per hour.

    Private subnet, no internet, reach S3 → gateway endpoint

    Endpoint policies

    A resource policy on the endpoint. Limits which buckets or actions pass through. Pair with aws:SourceVpce in the bucket policy.

    Session Manager

    Shell access to EC2 with no SSH keys, no port 22, no bastion host. Sessions logged to S3 / CloudWatch.

    AWS Network Firewall

    Managed stateful firewall for a whole VPC. Filters domains, IDS/IPS rules. Layer 3–7.

    Route 53 Resolver DNS Firewall

    Blocks DNS lookups to bad domains from your VPC.

    VPC Flow Logs

    Records who talked to whom (IPs, ports, accept/reject). Not packet contents. To CloudWatch Logs, S3 or Firehose.

    Lesson 6 · 8 min

    Stopping attacks before they reach you

    AWS WAF

    layer 7

    Web application firewall. Rules on HTTP requests.

    • SQL injection, XSS (managed rule groups)
    • Rate-based rules (block floods from one IP)
    • IP sets, geo match, header/string match

    Attaches to: CloudFront, ALB, API Gateway, AppSync, Cognito user pools. Not NLB, not EC2 directly.

    Shield Standard

    free

    Automatic for every customer. Protects against common layer 3/4 DDoS (SYN floods, UDP reflection).

    Shield Advanced

    paid
    • 24/7 Shield Response Team (SRT)
    • DDoS cost protection (refund of scaling costs)
    • Advanced detection and WAF included for protected resources

    Protects CloudFront, Route 53, Global Accelerator, ELB, Elastic IPs

    Firewall Manager

    many accounts

    Set WAF, Shield Advanced, security groups, Network Firewall and DNS Firewall rules once, across all accounts in an Organization. New accounts get them automatically.

    A DDoS-resilient design

    1. Route 53 for DNS (absorbs DNS floods at the edge).
    2. CloudFront in front, with WAF rate-based rules and Shield.
    3. ALB as the origin, in public subnets; instances in private subnets.
    4. Auto Scaling to absorb what gets through.

    Protecting the origin

    CloudFront + S3: OAC

    Origin Access Control lets only your CloudFront distribution read the bucket. Bucket stays private. (OAI is the older version.)

    CloudFront + ALB

    Add a secret custom header in CloudFront, and have the ALB (or WAF) reject requests without it. Or allow only the CloudFront managed prefix list in the ALB security group.

    Geo restriction

    CloudFront can allow or block whole countries.

    Signed URLs / cookies

    CloudFront signed URL = one file. Signed cookies = many files (a members area).

    Lesson 7 · 8 min

    S3 data protection

    S3 is in many security questions. These are the controls to know.

    Block Public Access

    Account-level and bucket-level switch that overrides any public policy or ACL. On by default for new buckets.

    Object Ownership

    "Bucket owner enforced" turns ACLs off. Default for new buckets. Control access with policies only.

    Pre-signed URLs

    Temporary link to get or put one object, with the creator's permissions. Up to 12 h from the console, up to 7 days with the CLI/SDK.

    Versioning + MFA Delete

    Keep every version. MFA Delete requires MFA to delete versions or turn versioning off. Only the root user can enable it, via CLI.

    Object Lock (WORM)

    Write once, read many. Needs versioning.

    • Governance: users with special permission can override
    • Compliance: nobody, not even root, can delete until retention ends
    • Legal hold: no end date, until removed

    Glacier Vault Lock

    A WORM policy on a Glacier vault. Once locked, it can never be changed.

    Access Points

    Many named entry points to one bucket, each with its own policy. Simplifies shared datasets.

    Access logs / CloudTrail data events

    Server access logs or CloudTrail data events show who read or wrote which object.

    Lesson 8 · 12 min
    
  
    The detective services
    
  
    Many look alike. Learn one sentence each, then play the matching game below.
    

  
    
    
    CloudTrail
    who did what
    Logs API calls: who, what, when, from where. Management events on by default (90-day history). Data events (S3 objects, Lambda invokes) are extra.
    Trail to S3 for long retention · organization trail · log file integrity validation
    
    
    AWS Config
    what changed
    Records resource configurations over time and checks them against rules. Can auto-remediate with SSM Automation.
    "compliance", "configuration history", "non-compliant security group". Detects, doesn't prevent.
    
    
    GuardDuty
    threats
    ML threat detection from CloudTrail, VPC Flow Logs and DNS logs (no setup of those needed). Plus S3, EKS, RDS logins, malware scans.
    "crypto mining", "compromised instance", "unusual API calls"
    
    
    Inspector
    vulnerabilities
    Scans EC2, ECR container images and Lambda for known CVEs and unintended network exposure.
    "vulnerabilities", "CVE", "patch level"
    
    
    Macie
    sensitive data
    ML scans S3 for PII and sensitive data (names, card numbers, credentials).
    "PII in S3", "GDPR data discovery"
    
    
    Security Hub
    one dashboard
    Collects findings from GuardDuty, Inspector, Macie and others across accounts. Runs best-practice checks (CIS, AWS Foundational).
    "single view", "aggregate findings", "multi-account"
    
    
    Detective
    root cause
    Builds a graph from logs to investigate a finding: which IPs, users and resources were involved, over time.
    "investigate", "root cause", "visualize"
    
    
    IAM Access Analyzer
    external access
    Finds resources shared outside your account or organization, and unused access.
    
    
    Trusted Advisor
    advice
    Best-practice checks: cost, security (open ports, root MFA), performance, limits. Full checks need Business support or higher.
    
    
    AWS Artifact
    compliance docs
    Download AWS's compliance reports (SOC, PCI, ISO) and accept agreements (e.g. HIPAA BAA).
    Audit Manager = collect evidence for your audits
    
  
    

  
    Auto-response pattern: GuardDuty / Config / Security Hub finding → EventBridge rule → Lambda or SSM Automation fixes it, SNS notifies the team.
