    Monitoring questions come in three kinds

    "How is it running?", "Who did what?", and "Is it configured correctly?" Each has its own service. Decide which kind of question you're reading and two of the four options disappear.

    How is it running?CloudWatchMetrics, alarms, logs, dashboards. Performance and health over time.
    Who did what, when?CloudTrailEvery API call: identity, time, source IP, parameters. Audit and forensics.
    Is it configured right?AWS ConfigResource configuration history and compliance rules over time.

    Try it: which service answers this?

    Pick a question above.

    Exam trap: CloudTrail tells you someone changed a security group. Config tells you what it looked like before and after and whether it now breaks a rule. CloudWatch tells you the CPU went up afterwards.

    CloudWatch metrics and alarms

    EC2 metricBy default?How to get it
    CPU utilizationYesBuilt in
    Network in/out, packetsYesBuilt in
    Status checks (system, instance)YesBuilt in, every minute
    Disk read/write opsInstance store onlyEBS volumes report their own metrics
    Memory utilizationNoCloudWatch agent (custom metric)
    Disk space usedNoCloudWatch agent (custom metric)

    The hypervisor sees CPU and network, not what is inside the OS. Anything inside the OS needs the agent.

    Resolution

    frequency
    • EC2 basic monitoring: 5 minutes, free
    • Detailed monitoring: 1 minute, paid. Faster Auto Scaling reaction
    • Custom metrics: 1 minute standard, down to 1 second high resolution

    Alarm states

    state machine

    OK, ALARM, INSUFFICIENT_DATA. An alarm fires when M of the last N periods breach the threshold.

    Alarm actions

    react
    • Notify an SNS topic (email, Lambda, Slack…)
    • Scale an Auto Scaling group
    • EC2 action: stop, terminate, reboot, recover
    • Systems Manager OpsItem / incident

    Composite alarms

    less noise

    Combine alarms with AND/OR, e.g. "CPU high AND latency high". Cuts alert fatigue.

    Recover action

    status check

    On a failed system status check, moves the instance to new hardware and keeps instance ID, private IP, Elastic IP and metadata.

    Anomaly detection

    ML band

    Alarm on a learned expected band instead of a fixed number. Good for metrics with daily patterns.

    Alarm simulator

    CPU pattern (one datapoint per period)

    Final state:

    Read the question for the time: "react within 1 minute" rules out basic monitoring (5-minute datapoints). "Memory" or "disk space" means the agent.
    Lesson 3 · 12 min

    CloudWatch Logs, the agent, and the extras

    Log groups & streams

    structure

    A group per app, a stream per instance or container. Retention defaults to never expire: set 1 day to 10 years to control cost. Encrypt with KMS.

    Metric filters

    logs → alarm

    Count matches like "ERROR" or statusCode=500, publish as a metric, alarm on it.

    Logs Insights

    query

    Interactive query language over log groups: filter, aggregate, top-N. Ad-hoc troubleshooting.

    Subscription filters

    real time

    Stream log events as they arrive to Kinesis Data Streams, Firehose, Lambda or OpenSearch. Cross-account log centralization uses these.

    Export to S3

    not real time

    CreateExportTask is a batch export that can take hours. For near-real-time delivery to S3 use a subscription filter → Firehose → S3.

    Live Tail

    debug

    Watch log events stream in as they happen while debugging.

    The unified CloudWatch agent

    What it collects

    • Memory, disk space, swap, processes (system metrics)
    • Application log files (e.g. /var/log/nginx/access.log)
    • Works on EC2 and on-premises servers
    • StatsD and collectd custom metrics

    How to roll it out

    • Install with Systems Manager Run Command or bake into the AMI
    • Store the agent config in SSM Parameter Store and share it across the fleet
    • Instance role needs CloudWatchAgentServerPolicy

    Specialized views

    Container Insights

    Metrics and logs for ECS, EKS and Kubernetes on EC2, per cluster, service, task and pod.

    Lambda Insights

    System-level metrics for functions: memory, CPU time, cold starts.

    Synthetics canaries

    Scripts that hit your endpoints or UI flows on a schedule, so you find outages before users do.

    RUM

    Real User Monitoring: page load and errors from real browsers.

    Dashboards

    Cross-Region and cross-account dashboards; share them with people outside AWS.

    Managed Grafana / Prometheus

    Managed open-source options when a team already uses Grafana dashboards or Prometheus metrics (common with EKS).

    CloudTrail: the audit log of every API call

    Event typeExamplesLogged by default?Cost
    Management eventsRunInstances, CreateBucket, PutBucketPolicy, AttachRolePolicy, ConsoleLoginYes · 90-day Event historyFirst copy in a trail free
    Data eventsS3 GetObject/PutObject, Lambda Invoke, DynamoDB item-levelNo · enable on a trailCharged per event
    Insights eventsUnusual spikes in write API calls or error ratesNo · enable on a trailCharged

    Management or data event?

    Pick an API call.

    Trails

    keep > 90 days
    • Deliver to an S3 bucket (and optionally CloudWatch Logs for alarms)
    • Multi-Region trail: one trail for all Regions
    • Organization trail: all accounts, created in the management account
    • SSE-KMS encryption

    Integrity

    tamper evidence

    Log file integrity validation writes SHA-256 digest files so you can prove logs were not changed or deleted. Add S3 Object Lock / MFA delete on the bucket for stronger protection.

    React to an API call

    near real time

    CloudTrail events appear in EventBridge. Rule on DeleteBucket or StopLogging → SNS or Lambda.

    Search and analyze

    SQL

    CloudTrail Lake: managed event store with SQL queries and long retention. Or query trail files in S3 with Athena.

    "Who deleted…", "which user changed…", "audit API activity" → CloudTrail. "Alert when someone disables CloudTrail" → CloudTrail event + EventBridge rule (or a Config rule).
    Lesson 5 · 14 min

    AWS Config and the operations toolbox

    Config recorder

    history

    Records configuration of supported resources and every change: timeline per resource, relationships (this ENI belongs to that instance).

    Config rules

    detective

    Managed rules (e.g. s3-bucket-public-read-prohibited, encrypted-volumes, restricted-ssh) or custom rules in Lambda/Guard. Evaluated on change or on a schedule.

    Remediation

    auto-fix

    Attach an SSM Automation document to a rule: non-compliant bucket → block public access automatically.

    Conformance packs & aggregators

    scale

    Packs bundle rules + remediation (e.g. CIS, PCI). Aggregators show compliance across accounts and Regions.

    Control typeStops it happening?Services
    PreventiveYesSCPs, IAM policies, permission boundaries, S3 Block Public Access
    DetectiveNo, reports itConfig rules, CloudTrail, GuardDuty, Security Hub
    CorrectiveFixes it afterConfig remediation (SSM Automation), EventBridge + Lambda

    Operations toolbox

    Systems Manager

    fleet ops
    • Session Manager: shell without SSH keys or open port 22, logged
    • Run Command: run scripts on many instances
    • Patch Manager + Maintenance Windows
    • Parameter Store: config and secrets
    • Automation: runbooks; Inventory

    X-Ray

    tracing

    Follows a request across API Gateway, Lambda, ECS, DynamoDB… Service map shows which hop is slow or failing. "Find the bottleneck in a microservice app" → X-Ray.

    Trusted Advisor

    best-practice checks

    Checks for cost, security, fault tolerance, performance and service quotas. All checks and the API need Business or Enterprise Support.

    AWS Health Dashboard

    AWS-side events

    Events affecting your resources: scheduled EC2 retirement, Region issues. Feed Health events into EventBridge to automate a response.

    EventBridge

    glue

    Routes events from CloudTrail, Config, Health, GuardDuty and scheduled rules (cron) to Lambda, SNS, SSM, Step Functions.

    Compute Optimizer

    right-size

    Uses CloudWatch history to recommend instance types, ASG, EBS, Lambda memory. Memory-based advice needs the agent.
