    Every analytics question is a pipeline with five stages

    Data comes in, gets stored, gets processed, gets queried, gets shown. Find which stage the question is about, and the answer list shrinks to two or three services.

    StageServices
    IngestKinesis Data Streams, Data Firehose, MSK (Kafka), IoT Core, DMS, DataSync
    StoreS3 (data lake), Redshift, OpenSearch, DynamoDB, Timestream
    ProcessGlue ETL, EMR, Managed Service for Apache Flink, Lambda
    AnalyzeAthena, Redshift (+ Spectrum), OpenSearch, EMR
    VisualizeQuickSight, OpenSearch Dashboards
    Govern (around all)Glue Data Catalog, Lake Formation

    Build a pipeline

    Real time

    Milliseconds to seconds. Kinesis Data Streams, MSK, Managed Flink, Lambda. Keywords: "real-time", "immediately", "sub-second".

    Near real time and batch

    Firehose buffers for seconds to minutes. Glue, EMR, Redshift for scheduled batches. Keywords: "within minutes", "nightly", "hourly".

    Shard calculator (provisioned mode)

    Shards needed

    Per shard: write 1 MB/s or 1,000 records/s; read 2 MB/s shared by all standard consumers, or 2 MB/s for each enhanced fan-out consumer. On-demand mode sizes shards for you.

    Partition key

    ordering

    Same key → same shard → in order. One busy key = a hot shard and throttling (ProvisionedThroughputExceeded). Fix: a high-cardinality key, or split the shard.

    Consumers

    reading
    • Lambda (event source mapping)
    • Kinesis Client Library apps on EC2/ECS
    • Managed Flink, Firehose
    • Enhanced fan-out: dedicated 2 MB/s per consumer, push model, lower latency

    Capacity modes

    pricing

    Provisioned: you choose shards, pay per shard-hour. On-demand: scales automatically with traffic, pay per GB. Unknown traffic → on-demand.

    Data Firehose in detail

    Sources

    Direct PUT from apps or agents, Kinesis Data Streams, MSK, CloudWatch Logs, AWS IoT, EventBridge.

    Destinations

    S3, Redshift (through S3 + COPY), OpenSearch, Splunk, HTTP endpoints and partners (Datadog, Snowflake…), Apache Iceberg tables.

    Transform on the way

    • Lambda to clean or enrich records
    • Convert JSON to Parquet or ORC (uses a Glue table schema)
    • Compress (gzip, Snappy)
    • Dynamic partitioning in S3
    • Failed records backed up to S3

    Lesson 3 · 15 min

    The S3 data lake: Glue, Lake Formation, Athena

    Put raw data in S3, describe it in a catalog, then query it with SQL without loading it anywhere.

    Glue Data Catalog

    metadata

    One central list of tables, columns, formats and partitions for data in S3 (and databases). Used by Athena, Redshift Spectrum, EMR and Lake Formation.

    Glue crawlers

    discover

    Scan S3 or databases, infer the schema and partitions, create or update catalog tables. Run on a schedule.

    Glue ETL jobs

    serverless Spark
    • Transform and convert (CSV → Parquet), join, clean
    • Job bookmarks: only process new data each run
    • Glue Studio (visual), streaming ETL, workflows and triggers

    Glue DataBrew

    no code

    Visual data preparation with 250+ ready transformations, for analysts who don't write code.

    Lake Formation

    govern

    Builds and secures the data lake on top of the Glue Catalog. Central permissions down to column, row and cell level, tag-based access control, cross-account sharing.

    "fine-grained access to the data lake" → Lake Formation

    Athena

    serverless SQL
    • Standard SQL directly on S3, no servers
    • Pay per TB scanned
    • Federated queries to RDS, DynamoDB and others via Lambda connectors
    • Workgroups set per-team limits and cost controls
    • Results saved to S3

    Saved vs plain CSV

    About $5 per TB scanned. Compression and column savings are typical values; real data varies. Columnar formats only read the columns you select. CSV always reads whole rows.

    Partitioning in S3

    s3://sales-lake/orders/year=2026/month=10/day=28/part-0001.parquet

    A query with WHERE year=2026 AND month=10 reads only that folder. Partition by the columns you filter on most, often date.

    Make Athena cheaper and faster: columnar format (Parquet/ORC) + compression + partitioning + bigger files (avoid millions of tiny files). Convert with a Glue job or Athena CTAS.
    Lesson 4 · 12 min

    Big processing, dashboards and search

    EMR: managed Hadoop and Spark

    What runs on it

    Spark, Hadoop, Hive, Presto/Trino, HBase, Flink. For huge batch jobs, ML pipelines, and teams that need full control of big data frameworks.

    Node types

    • Primary: coordinates the cluster
    • Core: runs tasks and stores HDFS data
    • Task: compute only, no data. Best for Spot

    Cost and deployment

    • Store data in S3 (EMRFS), so clusters can be transient: start, run, terminate
    • On-Demand or RIs for primary/core, Spot for task nodes
    • EMR Serverless or EMR on EKS: no clusters to manage
    NeedGlue ETLEMR
    ServersServerlessClusters (or EMR Serverless)
    ControlSpark with Glue featuresAny framework, versions, custom libraries, tuning
    Best answer when"serverless ETL", "least operational overhead", "catalog integration""Hadoop / Spark cluster", "migrate on-prem Hadoop", "custom frameworks", "petabytes"

    QuickSight: business dashboards

    What it is

    Serverless BI service. Connects to Athena, Redshift, RDS, S3, OpenSearch, SaaS apps. Readers pay per session.

    SPICE

    In-memory engine that imports data for fast, interactive dashboards.

    Extras

    ML insights (anomalies, forecasts), natural-language questions, row-level security, embedded dashboards in your app.

    OpenSearch Service

    Search and logs

    Full-text search (partial words, typos, ranking) and log analytics with OpenSearch Dashboards. Successor to Elasticsearch on AWS.

    Feeding it

    Firehose, OpenSearch Ingestion, CloudWatch Logs subscriptions, DynamoDB streams via Lambda. OpenSearch Serverless has no clusters to size.

    Common pattern

    DynamoDB is the main store; changes stream into OpenSearch so users can search by any field.

    Which SQL engine? Ad-hoc on S3, serverless → Athena. Frequent complex BI on loaded data → Redshift. Redshift users also need S3 data → Redshift Spectrum. Custom Spark/Hadoop → EMR.
