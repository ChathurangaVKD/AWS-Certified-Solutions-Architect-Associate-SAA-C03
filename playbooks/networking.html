    Lesson 1 · 10 min

    A VPC is your private network inside AWS

    You pick an IP range, cut it into subnets, and decide where traffic may go with route tables.

    VPC

    one Region

    Lives in one Region, spans all its AZs. IPv4 size from /16 (65,536 IPs) to /28 (16 IPs). You can add more CIDR blocks later.

    Subnet

    one AZ

    A slice of the VPC range, inside exactly one AZ. For high availability, use subnets in at least 2 AZs.

    Route table

    the map

    Each subnet uses one route table. Every table has a local route so all subnets in the VPC can reach each other.

    Internet gateway (IGW)

    highly available

    One per VPC. Lets traffic in and out to the internet. AWS scales it; no bandwidth limit to manage.

    What makes a subnet "public"? Only one thing: its route table has 0.0.0.0/0 → igw-…. The instance also needs a public IPv4 or an Elastic IP to be reachable.

    CIDR calculator

    Total addresses
    Usable in AWS (minus 5)
    Fit in a 10.0.0.0/16 VPC

    Smaller prefix number = bigger network. Each step up halves the size. Exam favourite: a /24 has 251 usable addresses.

    Other building blocks

    ENI

    Elastic Network Interface: a virtual network card with private IPs, a MAC, security groups. Can be moved to another instance in the same AZ.

    Elastic IP

    A static public IPv4 you own until you release it. All public IPv4 addresses are charged per hour.

    Default VPC

    One per Region, already built: /16, a public /20 subnet in each AZ, an IGW.

    DNS settings

    enableDnsSupport and enableDnsHostnames must be on for private hosted zones and interface endpoints to work.

    IPv6

    All IPv6 addresses are public and globally unique. A VPC gets a /56, subnets get /64.

    Flow Logs

    Records accepted/rejected traffic metadata for a VPC, subnet or ENI. Sends to CloudWatch Logs, S3 or Firehose.

    Egress-only internet gateway

    IPv6 only. Outbound to the internet allowed, inbound from the internet blocked. The IPv6 version of a NAT gateway.

    Bastion host

    An EC2 in a public subnet you SSH into, then hop to private instances. Modern answer: Session Manager instead.

    VPC endpoints

    Gateway (S3, DynamoDB): free, a route table entry. Interface (PrivateLink): an ENI with a private IP, most services, paid. Both keep traffic off the internet and avoid NAT costs.

    Cost trap: private instances pulling lots of data from S3 through a NAT gateway pay NAT data processing charges. Add an S3 gateway endpoint: free, and the more specific route wins.
    Lesson 3 · 10 min

    Connecting VPCs together

    Three tools: peering for a few VPCs, Transit Gateway for many, PrivateLink to share one service.

    Peering mesh vs Transit Gateway hub

    6 VPCs

    Full mesh = n × (n − 1) ÷ 2 connections, and every VPC's route tables must list every other VPC. A hub needs one attachment per VPC.

    VPC peering

    1-to-1
    • Not transitive: A↔B and B↔C does not give A↔C
    • No overlapping CIDRs
    • Works across accounts and Regions
    • Can't use the peer's IGW, NAT or VPN ("no edge-to-edge routing")
    • No hourly cost; pay data transfer
    • Update route tables on both sides

    Transit Gateway

    hub
    • Regional hub, transitive routing
    • Attach VPCs, Site-to-Site VPN, Direct Connect (via DX gateway)
    • Its own route tables → separate prod and dev
    • Peer TGWs across Regions
    • ECMP over many VPN tunnels for more bandwidth
    • Share across accounts with AWS RAM

    PrivateLink

    one service
    • Provider: service behind an NLB → endpoint service
    • Consumer: interface endpoint in their VPC
    • One direction only, consumer → service
    • Overlapping CIDRs are fine
    • Typical: SaaS for hundreds of customer VPCs

    VPC sharing

    RAM

    One account owns the VPC and shares subnets with other accounts in the Organization. They launch resources into the shared subnets. Fewer VPCs to manage.

    Lesson 4 · 12 min

    Connecting your data center to AWS

    VPN = fast to set up, over the internet, encrypted. Direct Connect = a private cable, consistent, slow to set up.

    Site-to-Site VPNDirect Connect (DX)
    PathOver the public internetPrivate dedicated line to an AWS DX location
    EncryptedYes, IPsecNo by default (add VPN or MACsec)
    Setup timeMinutes to hoursWeeks (often more than a month)
    SpeedUp to 1.25 Gbps per tunnelDedicated 1 / 10 / 100 Gbps (and 400); hosted from 50 Mbps
    LatencyVaries with the internetConsistent, predictable
    CostLowHigher; cheaper data transfer out at volume

    VPN parts

    • Customer gateway: your on-prem router (AWS needs its public IP)
    • Virtual private gateway on one VPC, or a Transit Gateway
    • Always 2 tunnels to two AWS endpoints for redundancy
    • Static routes or dynamic BGP
    • Accelerated VPN: rides Global Accelerator to AWS (TGW only)

    Direct Connect parts

    • Private VIF: to VPCs (via VGW or DX gateway)
    • Public VIF: to public AWS services like S3, over DX
    • Transit VIF: to Transit Gateways via a DX gateway
    • DX gateway: one DX to VPCs in many Regions
    • LAG: bundle several links into one

    Which hybrid answer?

    Client VPN

    Individual users on laptops connect to the VPC (OpenVPN-based). Not for whole offices.

    VPN CloudHub

    Several branch offices with VPNs to one VGW can reach each other through AWS. Hub and spoke, over the internet.

    DX resiliency

    High: 2 connections at 2 DX locations. Maximum: 2 connections at each of 2 locations, on separate devices.

    Lesson 5 · 12 min

    Route 53: DNS and traffic steering

    Turns names into IPs. The routing policy decides which IP each user gets.

    Hosted zones

    Public: answers the internet. Private: answers only inside the VPCs you associate.

    Record types

    A IPv4 · AAAA IPv6 · CNAME name → name · NS name servers · MX mail · TXT text

    TTL

    How long resolvers cache an answer. Lower before a migration so changes spread fast.

    Alias vs CNAME

    Routing policies

    Pick a requirement. The right policy lights up.

    PolicyWhat it doesHealth checks
    SimpleOne record; several values come back in random orderNo
    WeightedSplit traffic by percentage (e.g. 90 / 10)Yes
    LatencySends users to the Region with lowest latency for themYes
    FailoverActive-passive: primary while healthy, else secondaryRequired on primary
    GeolocationBy the user's continent, country or US state. Needs a default recordYes
    GeoproximityBy distance to resources; a bias grows or shrinks a regionYes
    Multivalue answerUp to 8 healthy records returned; client picks oneYes
    IP-basedBy the client's IP range (e.g. a specific ISP)Yes

    Health checks

    Check an endpoint (HTTP/HTTPS/TCP), other health checks (calculated), or a CloudWatch alarm. Checkers run on the internet, so for private resources use a CloudWatch alarm.

    Resolver: hybrid DNS

    Inbound endpoint: on-prem servers resolve AWS private names. Outbound endpoint + forwarding rules: AWS resources resolve on-prem names.

    Registrar ≠ DNS host

    You can buy a domain elsewhere and host DNS in Route 53: point the registrar's name servers to the hosted zone's NS records.

    CloudFront caches content at the edge. Global Accelerator puts users on the AWS backbone fast, with no caching.

    CachingYesNo
    Static IPsNoYes, 2 fixed IPs
    EndpointsS3, ALB, EC2, any HTTP origin, VPC originsALB, NLB, EC2, Elastic IPs in one or many Regions
    FailoverOrigin groups (primary/secondary origin)Health checks, Regional failover in under a minute

    CloudFront details

    Cache behaviors

    Different rules per path: /images/* to S3 with a long TTL, /api/* to an ALB with no caching.

    Invalidation

    Remove files from the cache before TTL ends. Cheaper habit: versioned file names (app.v2.js).

    Securing the origin

    S3: Origin Access Control (OAC). ALB: secret custom header or CloudFront prefix list. HTTPS cert from ACM in us-east-1.

    Edge code

    CloudFront Functions: tiny JS, viewer request/response only, sub-millisecond, cheapest (headers, redirects). Lambda@Edge: Node/Python, all 4 events, longer runs, network calls.

    Access control

    Signed URLs (one file) or signed cookies (many files). Geo restriction by country.

    Price classes

    Use fewer edge locations to cut cost (e.g. only North America and Europe).

    S3 Transfer Acceleration

    Faster long-distance uploads to one S3 bucket via edge locations. Different from CloudFront (delivery).

    Edge locations vs Regions

    Hundreds of edge locations worldwide serve CloudFront, Route 53 and Global Accelerator. Your resources still live in Regions.
