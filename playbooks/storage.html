    Lesson 1 · 8 min

    S3 is a giant key → file store

    No folders, no disks. You put an object (a file) into a bucket under a key (its full name), and get it back with an HTTP request.

    Bucket

    one Region

    A container. The name is globally unique across all AWS accounts (3–63 chars, lowercase). Data stays in the Region you choose.

    Object

    max 5 TB

    The file plus metadata, tags and a version ID. Any type of data.

    Key

    full name

    reports/2026/q3.pdf. "Folders" in the console are only key prefixes. The namespace is flat.

    Strong consistency

    After a successful write, overwrite or delete, the next read returns the latest data, everywhere. No more "eventual consistency" answers.

    Durability ≠ availability

    Durability: will my data be lost? (11 nines for every class.) Availability: can I read it right now? (99.99% for Standard, lower for IA classes.)

    Data transfer. Uploading into S3 is free. You pay for storage, requests, retrievals (IA and Glacier) and data transfer out to the internet or other Regions.

    Lesson 3 · 12 min

    Lifecycle rules move and delete data for you

    Two kinds of actions: transition (move to a cheaper class after N days) and expiration (delete after N days). Data only moves down to colder classes.

    Build a rule

      Filters

      A rule can target the whole bucket, a prefix (logs/), object tags, or object size.

      Versioned buckets

      Separate actions for noncurrent versions: move or delete old versions N days after they were replaced. Also remove expired delete markers.

      Clean-up rule

      "Abort incomplete multipart uploads after N days." Unfinished parts cost money and are invisible in the console.

      Not sure of the days?

      Storage Class Analysis watches access and recommends when to move data to Standard-IA.

      Intelligent-Tiering: automatic, no rules needed

      TierObject moves here afterAccess

      Infrequent Access30 days without accessms

      Archive Access (opt-in)90+ days, you chooseMinutes to hours

      Read one object in an infrequent tier and it moves back to Frequent automatically, with no retrieval fee. That is why "unknown access pattern" + "no operational overhead" = Intelligent-Tiering.
      Lesson 4 · 15 min

      Versioning keeps every copy. Replication copies to another bucket.

      Versioning simulator

      One object, report.pdf. Upload, delete, and watch what S3 really stores.

      Bucket versioning

      Three states

      Unversioned → Enabled ⇄ Suspended. Once enabled, never unversioned again. Suspending keeps the old versions.

      Delete marker

      A normal delete on a versioned bucket adds a marker. Older versions are still there. Remove the marker to "undelete".

      Cost

      Every version is billed as a full object. Use lifecycle noncurrent-version rules to clean up.

      MFA Delete

      MFA needed to permanently delete a version or suspend versioning. Root user only, via CLI.

      Replication: CRR and SRR

      Cross-Region (CRR)

      Compliance copies, lower latency for users in another Region, DR.

      Same-Region (SRR)

      Combine logs into one bucket, copy prod data to a test account, keep a copy under another account.

      RuleDetail
      VersioningMust be on in both source and destination
      PermissionsAn IAM role that S3 assumes to copy objects
      Existing objectsNot copied automatically. Use S3 Batch Replication
      DeletesDelete markers can be replicated (optional). Deleting a specific version is never replicated
      ChainingNo. A → B → C does not copy A's objects to C
      AccountsCross-account works; destination can use a different storage class and owner
      Speed SLAReplication Time Control (RTC): 99.99% of objects within 15 minutes

      Multi-Region Access Points

      One global endpoint for buckets in several Regions. Requests go to the nearest bucket; combine with replication for active-active and failover.

      Lesson 5 · 12 min

      Performance and everyday features

      Make S3 faster

      Multipart upload

      upload

      Split into parts (up to 10,000), upload in parallel, retry only failed parts. Recommended above 100 MB, required above 5 GB.

      Transfer Acceleration

      upload, far away

      Users upload to the nearest edge location; AWS carries it to the bucket over its backbone.

      Byte-range fetches

      download

      Download parts of an object in parallel, or only the header bytes you need.

      More prefixes

      request rate

      Limits are per prefix. 4 prefixes ≈ 22,000 GET/s. Getting 503 Slow Down? Spread keys across prefixes.

      CloudFront

      read-heavy

      Cache popular objects at the edge and offload the bucket.

      SSE-KMS throttling

      trap

      Every object = a KMS call. At high rates turn on S3 Bucket Keys.

      Features the exam names

      Event notifications

      On create/delete/restore events, send to SQS, SNS or Lambda. Send to EventBridge for advanced filters and many targets.

      "Generate a thumbnail when an image is uploaded"

      Static website hosting

      Endpoint http://bucket.s3-website-region.amazonaws.com. HTTP only, needs public read. For HTTPS and a custom domain: CloudFront + ACM + OAC.

      CORS

      A browser page from one origin loading files from a bucket on another origin needs a CORS rule on that bucket.

      Pre-signed URLs

      Temporary link to GET or PUT one object, using the signer's permissions. Up to 7 days with the SDK/CLI.

      Requester Pays

      The downloader pays request and transfer costs, not the bucket owner. Requester must be an authenticated AWS user.

      Batch Operations

      One job on billions of objects: copy, tag, change ACLs, restore from Glacier, invoke Lambda. Input from S3 Inventory.

      Inventory & Storage Lens

      Inventory: daily/weekly CSV or Parquet list of objects and their settings. Storage Lens: usage and activity dashboard across accounts.

      Access Points & Object Lambda

      Access Points: named endpoints with their own policy. Object Lambda: transform data on GET (for example redact PII).

      Query in place

      Use Athena to run SQL on files in S3. S3 Select is closed to new customers but can appear in older questions.

      Access control, encryption, Object Lock and Block Public Access are in the Security Playbook, lessons 3 and 7.

      Block and file storage

      S3 = objects over HTTP. EBS = a disk for one instance. EFS and FSx = shared file systems.

      S3EBSEFSFSx
      TypeObjectBlock (a disk)File (NFS)File (SMB, Lustre, NFS, iSCSI)
      Attach toAnything via HTTPSOne EC2 in the same AZThousands of Linux clientsMany clients
      ScopeRegionalOne AZRegional (multi-AZ) or One ZoneSingle- or Multi-AZ
      SizeUnlimitedYou provisionGrows and shrinks automaticallyYou provision

      EBS volume types

      TypeDiskUse it forRemember
      gp3SSDDefault: boot, most appsBaseline 3,000 IOPS and 125 MiB/s at any size; raise IOPS and throughput separately
      gp2SSDOlder defaultIOPS tied to size (3 per GB), burst credits
      io2 Block Express / io1SSDDatabases needing sustained high IOPSio2 BX up to 256,000 IOPS, 99.999% durability; Multi-Attach

      Snapshots

      Incremental, stored in S3 (managed by AWS). Copy to other Regions for DR. Automate with Data Lifecycle Manager. Recycle Bin protects against accidental deletes. Archive tier is about 75% cheaper.

      Multi-Attach

      io1/io2 only, same AZ, up to 16 Nitro instances. Needs a cluster-aware file system.

      Instance store

      Disks physically on the host. Highest IOPS, free with the instance. Data lost on stop, terminate or hardware failure. Use for cache, buffers, scratch.

      Fast Snapshot Restore

      Volumes from a snapshot are fully fast on first read, with no warm-up.

      EFS: shared Linux file system

      Basics

      • NFS v4, Linux only (not Windows)
      • A mount target in each AZ, protected by security groups
      • Works with EC2, ECS, EKS, Lambda, on-prem via VPN/DX

      Storage classes

      • Standard, Infrequent Access, Archive
      • Lifecycle moves unused files automatically
      • Regional or One Zone (cheaper)

      Performance

      • Throughput: Elastic (default, scales with load), Provisioned, Bursting
      • Performance mode: General Purpose (default), Max I/O (older, high parallelism)

      FSx: four managed file systems

      FSx for Windows File Server

      SMB

      Windows shares with Active Directory, NTFS permissions, DFS. Multi-AZ option.

      "Windows", "SMB", "AD integration"

      FSx for Lustre

      HPC

      Very fast parallel file system for HPC, ML, video rendering. Links to an S3 bucket: reads it as files, writes results back. Scratch (temporary, cheap) or Persistent (replicated).

      "HPC", "sub-millisecond", "process S3 data"

      FSx for NetApp ONTAP

      multi-protocol

      NFS, SMB and iSCSI at once. Snapshots, cloning, compression. Move NetApp workloads to AWS.

      FSx for OpenZFS

      NFS

      Move ZFS or Linux NFS workloads. Low latency, snapshots, cloning.

      AWS Backup

      One place to schedule and manage backups for EBS, EC2, EFS, FSx, RDS, Aurora, DynamoDB, S3 and more. Cross-Region and cross-account copies. Backup Vault Lock makes backups undeletable (WORM).

      Lesson 7 · 12 min

      Getting data from on-prem into AWS

      Online for ongoing or moderate amounts. Offline (a device by courier) when the network would take too long.

      Network or Snowball?

      100 TB
      Your internet link
      Over the network at 80% of the link
      ≈ 1 week
      Snowball, door to door

      DataSync

      online

      Moves files online, fast. An agent reads NFS, SMB, HDFS or object storage and writes to S3, EFS or FSx. Also between AWS storage services.

      • Schedules, bandwidth limits
      • Keeps metadata and permissions
      • Encrypts and verifies data

      "migrate", "scheduled sync", "NFS to EFS"

      Snowball Edge

      offline

      A rugged device shipped to you. Copy data locally, ship back, AWS imports into S3. Storage Optimized or Compute Optimized (edge processing, no connectivity).

      "slow / no network", "petabytes", "weeks would be too long"

      Transfer Family

      SFTP

      Managed SFTP, FTPS, FTP and AS2 servers that store into S3 or EFS. Partners keep their current tools.

      Snowcone and Snowmobile are retired but may still appear in older practice questions. Snowmobile was for exabyte-scale moves.

      Storage Gateway: hybrid storage that stays in use

      A VM (or hardware appliance) on-prem that gives local apps normal storage protocols, backed by AWS. Unlike DataSync, it is for ongoing use, not a one-time move.

      TypeProtocol on-premStored in AWS asUse case
      S3 File GatewayNFS / SMBS3 objects (one file = one object)File shares backed by S3, local cache of recent files
      Volume Gateway: cachediSCSIS3, recent data cached locallyExtend local block storage into AWS
      Volume Gateway: storediSCSIFull copy local, async backup to S3 (EBS snapshots)Low-latency access to all data, backups in AWS
      Tape GatewayiSCSI virtual tape libraryS3, archive to Glacier / Deep ArchiveReplace physical tapes, keep backup software

      FSx File Gateway (SMB cache for FSx for Windows) is closed to new customers but can appear in questions.

      One-time move → DataSync (online) or Snowball (offline). Keep using on-prem with cloud storage behind it → Storage Gateway. Ongoing big traffic, consistent latency → Direct Connect.
